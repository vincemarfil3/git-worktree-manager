What this extension actually needs

Chrome extensions are sandboxed — they're not allowed to run programs, read your files, or use git, on purpose, as a security boundary. So the popup you see is only half of this tool: the other half is a small helper program that runs on your own computer (not Chrome's), which the popup talks to whenever it needs to actually touch git or edit stories.json. Everything below is about getting that helper — called the native host — installed and connected. Until it is, the popup can still group tabs, but buttons like + New story and 🗑 won't work.

First-time setup

  1. Load the extension. Open chrome://extensions, turn on Developer mode (top-right toggle), click Load unpacked, and pick this story-tab-groups folder.
    Pin it to the toolbar while you're there (the puzzle-piece icon → the pin next to "Worktree manager") so it's always one click away.
  2. Run the setup script. This needs a terminal open in the same folder you just picked — in File Explorer, open that story-tab-groups folder, then either:
    • click into the address bar at the top, type powershell, and press Enter — or
    • hold Shift and right-click inside the folder (on empty space, not a file), then choose Open PowerShell window here (Windows 11: Open in Terminal).
    Once a terminal window opens with that folder already selected, run:
    .\setup.ps1
    This one command connects the native host, looks for your stories.json (and asks you where it is if it can't find it automatically), and runs a health check that tells you exactly what's missing if anything is. It's safe to run again any time — it only asks before changing anything that isn't a brand-new setup.
  3. Fully restart the browser. Close every Chrome window, not just this tab and not just a reload of the extension — the native host is only re-read when the browser cold-starts.
  4. Confirm it worked. Reopen the popup → Settings → the Native host card should show ✓ connected. The status card at the top of this page checks the same thing live.

Moving to a new computer, or replacing an existing install

Already have an older copy installed here? Use this section instead of First-time setup above, not after it — the command below is the exact same setup.ps1, just with one extra flag that also migrates the old install, so it does everything the plain version does plus the migration, in one run.

Copying this folder to a machine that already has an older copy needs one extra bit of care: Chrome has no way for one extension to remove another, so an old and new copy left loaded side by side will both try to manage the same tab groups. Your data (stories.json) is never at risk either way — this is purely about avoiding two copies of the popup fighting each other.

  1. Load the new folder unpacked, same as step 1 above.
  2. Go to chrome://extensions and remove or disable the old "Worktree manager" entry — there'll be two listed once both are loaded.
  3. From the new folder, run (with the old folder's real path in place of the placeholder):
    .\setup.ps1 -OldExtensionDir "<old story-tab-groups folder>"
    This carries over the old install's configured root, retires its old scripts (renamed, never deleted), re-points any scheduled EOD reminders, and unregisters the old native host — all in one pass, and it asks before each step unless you add -Force. Add -WhatIf first if you want to see exactly what it would do without changing anything.
  4. Fully restart the browser.
  5. Confirm it worked — same check as First-time setup's step 4: popup → Settings → Native host should show ✓ connected.
Advanced — install the native host without setup.ps1

If you'd rather just register the bridge and handle everything else (finding your stories.json, etc.) by hand, or setup.ps1 couldn't auto-detect this extension's id:

cd native-host
.\install-native-host.ps1 -ExtensionId …

Troubleshooting
Settings shows "✕ not connected"
Run .\setup.ps1 again from the extension folder, then fully restart the browser (every window). If that doesn't clear it, use the exact command Settings shows you — it has your extension's real id filled in already.
It was working, then I removed and re-added the extension in Chrome
Removing and re-adding (not just toggling Off/On) gives the extension a brand new id, which the native host no longer recognizes. Re-run .\setup.ps1 (or the Advanced command above) and restart the browser.
My stories aren't showing up in the popup
Open Settings → Worktree paths & branch format and check the Story root field — it needs to point at the folder your stories.json actually lives in. The Paths & diagnostics card right above it shows exactly what's currently configured and where each value came from.
I ran setup.ps1 (or changed Root) while Chrome was already open, and it's still using the old location
Fully quit Chrome — every window, confirmed via Task Manager that no chrome.exe is left running — then reopen it. This is different from reloading the extension: the native host runs as a child of the browser process itself, and it inherits whatever was true when that browser started, not whatever is true right now. An already-open browser can keep using a stale root long after Settings (and Paths & diagnostics) correctly show the new one — closing every window and reopening is the only way to clear that.
I see an error like "returned no JSON" or "host error"
This means the native host ran but something inside it failed. Settings' Paths & diagnostics card re-runs the same checks setup.ps1 does and will usually name the exact problem (a missing script, an unreadable stories.json, git not on PATH, …).
I moved the whole extension folder somewhere else
That's fine on its own — the extension finds its own scripts relative to itself, and moving files doesn't change its id. You only need to re-run the installer if you also removed and re-added the extension in Chrome (see above).

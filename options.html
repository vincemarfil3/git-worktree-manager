Your stories live in stories.json. This page shows what's loaded and lets you refresh it. First time here, or something not working? Help has a full step-by-step guide.

Projects

Each project is its own codebase — its own story root and organization settings. A worktree project also gets its own worktrees and app checklist (the original git-worktree workflow); a tracking project is a repo you work in a single VS Code window — just a story registry and one markdown doc per story living inside that repo, no worktrees or app checklist at all. The popup always shows whichever project is active; the cards below (Worktree paths, Organization settings, Apps) always act on that same active project — Set active above is the only way to change which one (Apps only applies to worktree-mode projects).

Worktree paths & branch format

Where the native host finds stories.json, where home-base app clones live, where per-story worktrees and the generated .code-workspace files are created, and how a new story's branch name is derived. Leave a field blank to use the default shown as its placeholder — an existing story keeps whatever root it was actually created under even if you change this later.

Organization settings

Links, GitHub-Actions matching, and the folder-name → repo-name alias — all org-specific, none hardcoded. Blank = the built-in default shown as the placeholder.

Apps

A repo cloned at your story root shows up below automatically. Add a port, start command and health path so the ⚡ ports/health button and story-env.ps1 can manage it — without one it just shows "unmapped". You can also map an app that isn't cloned yet, or hide one you never want offered in the + New story checklist (it stays listed here, unhide any time). Saved to app-map.json in this project's own folder, next to its stories.json — never the tools\ copy this ships with.

Advanced — other ways to update

Sync from stories.json — a fallback for when the native host is unreachable (Settings' Rules source card above would otherwise show a stale/empty list with no way to refresh it). stories.json now gets created automatically in a project's own folder the moment you add it, and the native host reads it live, so this manual picker is no longer needed for the normal case.
